# Agent trace audit preregistration: SWE-agent workload opportunity

Frozen before labeling any SWE-agent turn-level safe/unsafe counts.

## Primary Question

Does a real coding-agent workload contain enough generation turns whose next action is dominated by
the current task and latest environment observation to justify a request-level reuse gate?

The question is not whether the agent carries long history. It does. The question is whether each
generation actually needs to reason over old intermediate history.

## Workload

Primary workload: `ElenaFu/SWE-agent-trajectories`, a duplicate of
`nebius/SWE-agent-trajectories`, train split. The dataset card reports 80,036 SWE-agent-style
trajectories with model generations and environment observations.

Sampling plan:

- Pilot: 20 trajectories, contiguous from offset 0, to validate parsing and label rubric.
- Main trajectory frame: 100 trajectories, deterministic random row offsets with fixed seed 0.
  Four rows that repeatedly returned HTTP 429 were skipped, leaving 96 trajectories and 2,739
  generation turns.
- Manual audit: 400 unique turns sampled from that frame with seed 0, proportionally stratified by
  `command_family x target`. This stratification does not use heuristic labels.
- Two annotators independently label disjoint halves plus a proportionally sampled 100-turn
  overlap. This gives 250 items per annotator and 500 total judgments before adjudication.
- Report target/resolved and unresolved trajectories separately, then pooled.

No GPU generation is used.

## Unit of Analysis

One row may contain many messages. Each assistant/AI message is one agent generation turn.

For generation turn `t`, define:

- current task: the initial issue/instruction user message;
- latest observation: the nearest prior user/environment message before `t`;
- old intermediate history: prior assistant/actions and environment observations before the latest
  observation, excluding the current task and system prompt.

## Labels

Primary labels are assigned at the turn level:

- `safe`: current task plus latest observation are sufficient to choose the next action; old
  intermediate history is not materially needed to perform this particular generation correctly.
- `history_dependent`: choosing the next action requires facts, constraints, or intermediate
  conclusions from old history.
- `ambiguous`: the turn cannot be confidently classified from the logged text.
- `bookkeeping`: malformed retries, formatting-only responses, or non-substantive wrapper turns.

Heuristic labels generated by `agent_trace_audit.py` are not primary results. They are triage only.
Primary counts must use manual or adjudicated labels.

The manual decision is a strict counterfactual: if old history were unavailable, would information
needed to justify or execute this particular generation be missing? Merely being able to guess a
plausible next action is insufficient. In particular:

- a latest test failure does not make the next action safe when choosing that action or file relies
  on an earlier plan;
- inspection/navigation is history-dependent when its target or purpose comes from earlier search,
  diagnosis, or planning;
- an edit is history-dependent when it uses code content or intended changes seen only earlier;
- old history that is only provenance or repeats the task/latest observation does not create a
  dependency.

Annotators see the full current task, full old history, latest observation, and current generation.
They do not see heuristic labels, trajectory outcome, original turn keys, or each other's labels.
Every `history_dependent` judgment records the specific required old-history fact. Disagreements are
adjudicated; `ambiguous` remains a valid final label and is not forced into a binary category.

## Metrics

Primary:

```text
f_safe = # safe / (# safe + # history_dependent + # ambiguous)
```

`bookkeeping` turns are excluded from the denominator and reported.

Secondary:

- same rates by target/resolved status;
- same rates by command kind (`open`, `search`, `edit`, `submit`, shell, etc.);
- estimated cold-history token share per turn using a character/4 token proxy;
- oracle context compute saving:

```text
S_oracle = sum(cold_history_tokens for safe turns)
           / sum(total_context_tokens for non-bookkeeping turns)
```

This is intentionally a rough workload headroom estimate, not a runtime claim.

Primary reporting uses inverse-stratum weights and ambiguity bounds:

```text
S_lower: count ambiguous turns as history-dependent
S_upper: count ambiguous turns as safe
```

The same lower/upper construction is reported for `f_safe`. Report raw overlap agreement and
Cohen's kappa. Sampling uncertainty is an approximate 95% cluster bootstrap interval over
trajectories, with seed 0 and 10,000 trials. Both the ambiguity bound and its confidence interval
must be shown; a midpoint estimate is not a primary result.

## Decision Rule (Manual Workload Gate)

- `GO`: the lower endpoint of the 95% CI for ambiguity-conservative `S_lower` is above 0.30.
- `STOP`: the upper endpoint of the 95% CI for ambiguity-optimistic `S_upper` is below 0.20.
- Otherwise: inconclusive; increase the manual sample or inspect tau-bench before spending GPU.

Only after `GO` may one cheap request-level gate experiment be run. No additional dLLM
characterization is performed before this workload gate.

## Deviations Log

- The initial provisional rule (`f_safe >= 0.60` and `S_oracle >= 0.40`) was replaced before manual
  labeling by ambiguity bounds and sampling CIs. This reflects the preregistered manual-audit design
  rather than heuristic triage counts.
